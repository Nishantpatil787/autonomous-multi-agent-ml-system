# Reproducibility

How to reproduce the documented results. Everything is local, deterministic and
free of credentials: there are no API keys, no account settings and no secrets
anywhere in the project, so there is nothing sensitive to redact here. All paths
are relative to the project root.

---

## 1. Environment

- Python **3.12.3** (`requirements.txt` targets 3.11+).
- Verified package versions (the environment the Phase 11 benchmark and the
  Phase 12 validation ran in):

| Package | Version |
|---|---:|
| pandas | 3.0.1 |
| numpy | 2.4.2 |
| scikit-learn | 1.8.0 |
| optuna | 4.9.0 |
| langgraph | 1.2.12 |
| joblib | 1.5.3 |
| streamlit | 1.65.0 |
| mlflow | 3.16.1 |
| matplotlib | 3.11.2 |
| pytest | 9.1.1 |

The optional LLM layer adds **no** Python dependency (it speaks HTTP to Ollama
with the standard library).

## 2. Random seed

- All stochastic operations are seeded with **random_state = 42**
  (`utils/config.py::RANDOM_STATE`), including Optuna's own
  `OPTUNA_RANDOM_SEED = RANDOM_STATE`.
- Hold-out split: `test_size = 0.2`, stratified when every class allows it.
- Cross-validation: `StratifiedKFold(5, shuffle=True, random_state=42)`, with a
  documented safe reduction when a fold would lose a class.

## 3. Datasets and hashes

The two committed sample datasets have stable SHA-256 hashes asserted by tests
(`tests/helpers.py`):

| Dataset | Rows × Columns | Features used | Target | Split (train/test) | SHA-256 |
|---|---:|---:|---|---|---|
| `datasets/sample_classification.csv` | 123 × 9 | 7 | `Outcome` (binary) | 96 / 24 | `49ea0e2964cfce753578f23753352b453167e3f48b902a53562e1cd98f8fd23c` |
| `datasets/sample_multiclass.csv` | 92 × 7 | 5 | `class_label` (3-class) | 72 / 18 | `0b70768d76af4aa27384a2c7eeb57587e85a6e775b1142c4cb81526e376539a8` |

`benchmarks/benchmark_config.py` also pins these hashes, so a benchmark run
refuses to proceed on modified data.

## 4. Reproduce the benchmark

```bash
python app.py --benchmark --all            # both datasets, recorded
python app.py --benchmark --all --no-mlflow   # identical, no recording
```

Benchmark contract (enforced by tests):
- same split, same preprocessing defaults, same five candidate families, same
  weighted metrics on both sides;
- **conventional** side: tools-only, 21-config grid (no agents/LangGraph/LLM/
  Optuna);
- **autonomous** side: the existing `run_workflow` graph, LLM off, Optuna on
  (20 trials per tuned model), persistence to a scratch directory, tracking to
  the dedicated benchmark store;
- MLflow failure never fails the benchmark; `--no-mlflow` is honoured with
  `--benchmark`; the canonical `experiments/tracking/` store is never touched
  by a benchmark (asserted by the artifact-isolation guard).

Outputs recreated by the command:

| Artifact | Contents |
|---|---|
| `reports/phase11_comparison.json` | per-dataset conventional/autonomous records, deltas, verdicts, node timings |
| `reports/phase11_comparison.csv` | flattened summary table |
| `reports/phase11_f1_comparison.png` | F1 comparison chart |
| `reports/phase11_runtime_comparison.png` | runtime comparison chart |
| `reports/phase11_experiment_comparison.png` | experiment-count comparison chart |

## 5. MLflow configuration

- No server. Local SQLite stores created automatically:
  - canonical store `experiments/tracking/mlflow.db` — only `--graph` runs
    record here; experiment default name **`autonomous-multi-agent-ml`**;
  - benchmark store `experiments/tracking_benchmark/mlflow.db` — experiment
    **`benchmark-phase11`**, used only by `--benchmark`.
- Recording is on by default for `--graph`, off by default for the sequential
  path, and disable per run with `--no-mlflow` or `MLFLOW_ENABLED=false`.
- Overrides (all optional, none a credential): `MLFLOW_TRACKING_URI`,
  `MLFLOW_EXPERIMENT_NAME`, `MLFLOW_HISTORY_LIMIT` — see `.env.example`.

## 6. Reproduce a workflow run

```bash
python app.py --graph --dataset datasets/sample_classification.csv   # full pipeline + Optuna + persistence + tracking
python app.py --graph --no-optimize                                  # baseline-only variant
python app.py --no-optimize                                          # sequential path
```

## 7. Reproduce the test result

```bash
pytest -q
```

Final measured result: **1887 passed, 0 failed, 7 warnings, 1369 subtests
passed, exit code 0** (≈ 7 min on the audit machine; the suite gained three
config regression tests during the final release audit, see
`reports/final_evaluation_report.md`). Tests assert dataset hashes, model and
MLflow artifact integrity, benchmark fairness, dashboard section behaviour and
the byte-level isolation of `models/` and `experiments/tracking/` from tests
and benchmarks.

## 8. Reproduce the final diagrams

The three Phase 12 diagrams are generated by one small script that uses only
matplotlib (already a project dependency):

```bash
python make_final_diagrams.py
```

| File | Source data | Generator |
|---|---|---|
| `reports/final_architecture.png` | the documented agent pipeline and optional LLM layer | `make_final_diagrams.py` |
| `reports/final_workflow.png` | the compiled graph routing (`Should Optimize?`) | `make_final_diagrams.py` |
| `reports/final_comparison.png` | `reports/phase11_comparison.json` | `make_final_diagrams.py` |

They are static documentation assets; re-running the benchmark regenerates
`phase11_*` charts and the comparison data they display. Re-running a workflow
regenerates `models/*` and the dashboard renders the newest run.
